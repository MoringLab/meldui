# Safe content implementation — 2026-10-10

This record is separate from Phase 1 and the earlier Phase 2 baseline. The original 30 fixture messages remain unchanged. The shared catalog now includes 35 semantic components (the original 25 plus ten content components). `Image` retains the trusted bundled-asset path.

Implemented: safe built-in GFM/code/math display on React, RN and Flutter; host replacement API; Markdown inside surfaces; host attachment registries, identifier-only model views, bounded resolver handling; gallery/count layouts, image compare, host region references, video/audio/file cards and declared platform fallbacks. Host-owned synthetic images/video/audio/PDF fixtures exercise the display contract. They are replay fixtures, not model generations.

Security: raw HTML removed; native Markdown cannot auto-load images or preview external links; HTTPS/exact-origin checks with an explicit localhost fixture exception; MIME/size checks; at most one expired-result refresh; cancellation/lifecycle cleanup; no default external navigation or autoplay; signed URL queries excluded from persisted history. Actual HTTP redirect and response Content-Type verification stays with the trusted host resolver/proxy. Fenced code remains literal. Full adversarial LLM injection success rates have not been measured; no claim of 100% prompt-injection immunity is made.

Verification counts and final build/device outcomes are appended below when completed. Raw logs are in `artifacts/m5-*`. Optional extensions still open: raw-HTML formatting allowlist, image zoom, interactive compare scrubber, native caption tracks/chapter controls and native code colorization. Flutter audio is explicitly advertised as unsupported with FileCard fallback; PDF preview also falls back until the host supplies a viewer. None of these gaps is silently counted as feature parity.
