# Custom components, portable scenes and code artifacts

MeldUI retains the v0.9 A2UI wire, original fixtures and `@engine/*` names. Additive APIs let the host extend its catalog and completely replace answer presentation. Authored replays demonstrate capability; model-generated quality is evaluated separately.

## Registering a component

```tsx
import { z } from 'zod';
import { componentProps, defineComponent } from '@engine/protocol';
import { extendKit } from '@engine/kit-spec';
import { neutral } from '@engine/kit-neutral';
import { createUIRuntime, UIProvider, AnswerView } from '@engine/renderer-react';

const ProductSummary = defineComponent({
  name: 'ProductSummary',
  description: 'A product summary with host-owned actions and a named detail slot.',
  schema: z.object({
    title: componentProps.text,
    detail: componentProps.child,
    action: componentProps.action,
  }),
  slots: ['detail'],
  actions: ['openProduct'],
  examples: [{title: 'Example product', detail: 'detail-node', action: {event:{name:'openProduct'}}}],
  platforms: ['web', 'react-native', 'flutter'],
});
const catalogId = 'urn:my-product:ui:1';
const runtime = createUIRuntime({catalogId, customComponents: [ProductSummary], onAction: hostAction});
const kit = extendKit(neutral, [ProductSummary], catalogId);
const components = {
  ProductSummary: ({node, renderChild, runtime, surfaceId}) => (
    <section>
      <h3>{node.props.title}</h3>
      {renderChild(node.props.detail)}
      <button type="button" onClick={()=>runtime.dispatch(surfaceId,node.id,node.props.action,node.scope)}>Open</button>
    </section>
  ),
};
// Wrap <AnswerView session={session}/> with <UIProvider runtime={runtime} kit={kit} components={components}/>.
```

Definitions contain portable schemas, descriptions, slots, actions, examples and platform support; implementation functions stay in the trusted host registry. `componentProps.child/children` preserve upstream graph/reference semantics. React Native uses `NativeViewProps.renderChild` with native controls. Flutter loads the generated catalog JSON into `UIRuntime.create(schema: ...)` and supplies `UIProvider.components` builders; `UIComponent(surfaceId: ..., componentId: ...)` renders a referenced child. All custom inputs write through the runtime and all actions use the same dispatcher.

The studio contains `PartInspector`, `EquationControls` and `ReservationCard` consumers. Their source is illustrative host code, not executable code delivered by a model. Extending a Kit does not grant permission to call business tools or import arbitrary modules.

## Complete presentation replacement

Web/RN `AnswerView.renderSurface` and `renderLayout`, and Flutter `surfaceBuilder` and `layoutBuilder`, remove mandatory SDK frame chrome. A host can own toolbar, loading, error and layout presentation. Web `UISurface` also accepts `renderLoading`/`renderError`. Component registries replace Markdown, Formula, media, Chart, SvgScene and inputs just like any other component. Content providers replace Markdown and attachment renderers. Inline/fullscreen/PiP are host-controlled web display modes; a host must provide its modal/focus and lifecycle behavior.

`/service.html` demonstrates chrome-free, host-themed composition. Seven ordinary catalog fixtures implement purchase filtering/sorting, period KPIs, quizzes, conditional settings, an SVG progress ring, a numerical ecology illustration and a media mosaic. They use synthetic data and local state; saving actual settings or reservations requires host APIs. Carousel, comparison, enlargement and side-by-side Markdown media layouts remain supported. Attachment bytes/URLs are resolved by the host, never generated by the model.

## Compiling SVG and linking state

```ts
import { compileSvg } from '@engine/core';
const compiled = compileSvg(svgSource, {
  title: 'Assembly', description: 'Move and inspect its parts',
  parts: {
    wheel: {
      label: 'Front wheel',
      explode: {path:'/separation', x:100, y:0},
      action: {functionCall:{call:'setValue',args:{path:'/selectedPart',value:'wheel'}}},
    },
    piston: {keyframes:{path:'/blend',from:{y:0,angle:0},to:{y:-50,angle:15}}},
  },
});
// Add {id:'scene',component:'SvgScene',...compiled.scene} and bound Slider components.
```

SVG is compiled once into inert common scene data. XML/element/depth/path limits apply. Supported source elements are svg, g, rect, circle, ellipse, line, polyline, polygon, path, text, title and desc. Geometry, safe colors and selected presentation attrs are allowed. Scripts, event attributes, DTD, external references, CSS classes/styles outside the allowlist, filters, images and foreignObject are rejected. Source defs/gradients/clips are currently unsupported; the existing JSON scene contract supports its bounded gradients and rectangular clips directly.

Typed translate/rotate/scale transforms and numeric attribute bindings change groups without recompiling SVG. Keyframe interpolation is clamped to 0..1; explosion scales offsets by the referenced state value. Web supports part selection, zoom/pan and reset; Flutter supports its portable transforms, zoom/pan and semantic part actions. RN supports portable transforms/actions and explicit controls; continuous scene dragging remains capability-gated. Neither LaTeX nor SVG is treated as computation: validated expressions calculate values and KaTeX renders equations with trust disabled.

## Generation and revisions

`planPresentation()` selects Markdown/components/scene/media/code under actual host policy and target capabilities. The local server then injects only relevant catalog guidance and dev examples. Streaming `renderScene`, `renderAnswer` and opted-in `renderApp` tool calls are validated after completion; routes without reliable tool support retain the NDJSON path. Partial app previews contain complete CSS/HTML fields and never execute partial JavaScript. The automatic path permits at most three requests: classification, generation, one correction. Gateway/auth/rate/transport failures retain their infrastructure reason and bypass schema repair.

`AnswerSession.updateArtifact(id, expectedRevision, update)` validates a scoped replacement before applying it. TS supports Markdown, surface and allowed code source updates. Flutter's async equivalent supports Markdown and portable surface updates. Dirty inputs retain their values and conflicting model writes remain pending. Revisions persist in history; stale revisions fail. Code snapshots use `saveArtifactState`; secrets and signed URL parameters are redacted from history.

## Host tools and live widgets

`HostBridge` exposes only registered schema-validated tools and explicitly readable/writable state paths. Required confirmation is obtained from the real host before a handler runs. Cancellation/disposal rejects late results. It limits argument/result size and concurrent calls; audit hooks receive lifecycle status without raw private values.

A web host may opt into `AppRuntimeProvider` with `kind:'live'`, `assurance:'browser'`. Widgets run inside an opaque iframe and receive approved bundles, Kit CSS variables and a token/source-checked bridge. Theme changes preserve program state. CSS/HTML previews and html mode prohibit scripts; completed app mode permits them. The demo resource loader accepts only fixed IDs for Three.js, D3, Chart.js, KaTeX and GSAP; models never choose module URLs or CDN paths. A trusted prebuilt custom-element bundle can expose host web components inside the iframe.

Iframe isolation does not enforce hard CPU/memory limits or prove all network pathways blocked. The separate verified Docker/Chromium provider retains resource limits, network-none execution, external watchdog and attack attestation. Native code artifacts display their declared fallback unless the host supplies a supported native implementation. Ordinary inputs and SVG scenes do not require a sandbox.

## Optional interoperability

`@engine/adapter-copilotkit` exports frontend tool descriptors through HostBridge, explicit shared-state access, a MeldUI activity renderer and a validated Open Intelligent UI activity converter. Supply a distinct answer session per activity; mark cumulative wire content `complete:true` only when generation finishes. `@engine/adapter-mcp-apps` exports standard MCP Apps UI resources, App connection, tool results and an AppBridge backed by HostBridge. These are optional packages; they do not become core dependencies or grant additional permissions. See their package READMEs for registration.
