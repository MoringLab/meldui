# Security boundaries

Tier 1/2 accept validated catalog data and pure bounded expressions. Model output, attachment text and diagnostics are untrusted; host code, statically registered kits, resolvers and simulation modules are trusted. Credentials remain server-only, and demos bind to loopback. Unknown components, prototype paths, impure expression actions, unapproved asset origins and fabricated IDs are rejected. Media/vision are separate permissions; images are not sent to a model merely because they are rendered. History excludes signing URLs and opaque handles.

Markdown strips raw HTML. The optional formatting flag accepts only text-only, attribute-free b/strong/i/em/s/del/code pairs. Links/actions still require a host resolver/callback. Patched KaTeX runs with trust disabled, bounded expansion and a literal fallback. Hosts own download/redirect MIME enforcement, asset retention, consent and external-link confirmation.

Generated app code is limited to the opt-in web sandbox provider: Docker network none, separate sandboxed Chromium, read-only/capped resources, external watchdog and a validated replay bridge. It is not same-origin DOM or host Node execution. No local attestation means no app enablement. Eleven local attack cases are not a production isolation certification. Native sandbox is unsupported.

The reservation consumer separates business authorization from generated UI: host sessions, CSRF, one-use server confirmations, per-user idempotency and persistent audit. Its demo password/accounts are examples, not a production identity service. Do not expose demo/model/sandbox/reservation endpoints publicly without your own authenticated session policy and deployment review.

Dependency audits and unresolved transitive advisories are retained in the dated report. Workspace overrides do not replace downstream owners' dependency policies. A private reporting address and repository/package ownership remain pending; report issues privately to the maintainer and never include credentials in an issue.
