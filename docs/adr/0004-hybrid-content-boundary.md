# ADR 0004: hybrid answers and host-controlled content

Accepted 2026-10-10. Existing A2UI v0.9 operations stay intact. The additive v1 answer carrier interleaves Markdown and control declarations; `AnswerSession` also composes separate text and UI channels. Stable block IDs and monotonically increasing sequence numbers support replay. New surfaces require readable fallback text. History schema 2 migrates legacy surface-only messages. Credentials, attachment handles and signed query strings are not persisted.

Markdown is the default for simple answers. Host policy governs surface/media limits, renderer capabilities and sandbox availability. It is enforced by the runtime as well as described in the prompt. A Markdown-only policy cannot allocate surfaces. Sandbox remains disabled.

For M5, [react-markdown](https://github.com/remarkjs/react-markdown) plus remark GFM/math and KaTeX render web content. Raw HTML has no parsing plugin and is dropped before rendering. The KaTeX configuration disables trusted commands and caps expansion. Its fonts are packaged locally. [Enriched Markdown](https://enriched.swmansion.com/markdown/) renders native text in RN, after an mdast boundary removes all raw HTML and library-owned image loading. Link previews are disabled. Flutter uses [flutter_markdown_plus](https://pub.dev/packages/flutter_markdown_plus) and [flutter_math_fork](https://pub.dev/packages/flutter_math_fork); images are replaced by a host-controlled builder, and links have no default navigation. Hosts can replace all three Markdown renderers.

Host attachments are registered metadata, never generated/uploaded/stored file bytes. URLs resolve from IDs only. Exact origins, schemes, MIME and size are checked before display/actions. A resolver timeout and at most one expired-result refresh prevent unbounded failure retries. View unmounts cancel/ignore late resolution and release timers. Signed URLs are refreshed for display, and excluded from model-visible views and history. The host must verify redirects and actual response Content-Type through its own controlled proxy; the SDK cannot constrain a third-party server's HTTP redirects after an image/video request.

`Image` retains its legacy bundled-asset path and adds an attachment ID path. Galleries adapt by count; unknown IDs are diagnosed. Image annotations refer to host-supplied region IDs, with normalized coordinates, rather than fabricated model coordinates. Video uses native/browser controls and host transcripts; autoplay is disabled in default renderers. Audio on Flutter is declared unsupported with a FileCard fallback; document preview defaults to FileCard pending a host viewer. No arbitrary PDF iframe is used.

This is additive catalog evolution under the preview catalog ID. Hosts should negotiate `components` explicitly; a renderer for the earlier 25-component catalog is not claimed to implement the new content components. Existing 30 fixture messages remain valid. Third-party package notices are recorded in NOTICE. Network/media/iOS execution evidence is recorded per platform; a successful unit test is not device proof.
